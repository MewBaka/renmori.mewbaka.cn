# Ren'Py のアンパック・逆コンパイル対策ガイド

「Ren'Py 暗号化」「unrpyc 対策」「rpa 暗号化」「素材 抜き出し 防止」などで検索する開発者が抱えている問題は、たいてい同じです。ゲームを公開すると、シナリオ・立ち絵・CG・音声が `unrpa`、`rpatool`、`unrpyc` などの既存ツールでワンクリックで抜き出され、再配布されてしまうことです。

本ページでは、Ren'Py ゲームが簡単にアンパックされる理由、よくある対策ではこれらのツールを防げない理由、RenMori がアンパックと逆コンパイルを防ぐ仕組み、そしてクライアント側の保護ではできないことを説明します。

## Ren'Py ゲームが簡単にアンパックされる理由

Ren'Py 独自の 2 つの形式は、どちらも暗号化されていません。

- **`.rpa` アーカイブ**は、インデックスとファイルを順に連結しただけのもので、せいぜい XOR による「難読化」キーが付く程度です
- **`.rpyc` スクリプト**は、Ren'Py の AST を pickle 化して zlib で圧縮したもので、デコンパイラは pickle を復元するだけで `.rpy` ソースを再構成できます

Ren'Py の公式ドキュメントも難読化は気軽な閲覧を防ぐ程度だと認めており、主要開発者はアセット暗号化の機能要望を実現不可能として閉じています（[renpy/renpy#2546](https://github.com/renpy/renpy/issues/2546)）。そのため、公開されているツールはほぼすべてアンパックする側のものです。

| ツール | 機能 |
|--------|------|
| `unrpa` | `.rpa` アーカイブを展開する。RPA-1.0〜4.0 と各種派生形式に対応 |
| `rpatool`、`RenPack` | `.rpa` アーカイブの一覧表示・展開・書き換え。XOR キーにも対応 |
| `RenpyEx` | `.rpa` と `.rpyc` を展開し、`options.rpy` からキーを自動検出する |
| `unrpyc` | `.rpyc` を逆コンパイルする。`--try-harder` による難読化解除に対応 |
| `un.rpyc` | `game/` に置くとゲームと一緒に読み込まれ、プロセス内から全スクリプトを書き出す |
| `rpycdec` | `.rpyc` と `.rpymc` を逆コンパイルする |

## よくある対策が効かない理由

コミュニティで広まっている対策の多くは、ファイルの見た目を変えるだけです。上のツールはそうした変更にすでに対応しています。

- **`.rpa` の名前変更、アーカイブヘッダーや `loader.py` の書き換え**：`unrpa` は各種派生形式に対応しており、`RenpyEx` は `options.rpy` からキーを自動検出できます
- **`.rpyc` のマジックナンバー変更、zlib・base64・hex によるペイロードの包み直し**：unrpyc の難読化解除モジュールが改変されたヘッダーを走査し、zlib・hex・base64・エスケープのデコードを最大 10 層まで順に試します
- **スクリプトを画像ファイルに隠す、ホワイトリストのアーカイブだけを読み込ませる**：簡単に回避できるか、効果が検証されていません
- **Ren'Py 標準の難読化**：公式ドキュメント自体が、気軽な閲覧を防ぐ程度だとしています

これらのツールを本当に無効化するには、RPA と標準の pickle 形式を完全にやめ、ビルドごとに形式を変える必要があります。詳しい調査は[既存手法の調査](../technical/research.md)を参照してください。

## unrpa・rpatool による展開を防ぐには

RenMori は RPA アーカイブを使いません。スクリプト・立ち絵・CG・音声・動画・フォント・翻訳・設定をすべて暗号化コンテナに封入し、実行中のエンジン内部でのみ復号します。復号済みのファイルがディスク上に残ることは一切ありません。

保護済みビルドのディスク上には `.rpa` ファイルが存在しないため、`unrpa`、`rpatool`、`RenPack`、`RenpyEx` のように RPA を読むツールは手の付けようがありません。このうち `unrpa` は保護済みビルドで実際に失敗することを確認済みで、残りはまだ個別には試していません。コンテナの公開仕様は[コンテナ形式 v1 の仕様](../technical/container-format.md)にあります。

## unrpyc による逆コンパイルを防ぐには

鍵の漏えいやメモリダンプによってコンテナの中身が露出した場合に備え、スクリプトには独立した保護層があります。RenMori はビルド時に各 `.rpyc` の pickle ペイロードを AES-256-GCM の暗号文に置き換え、スクリプト鍵はコンテナ鍵とは別に管理します。デコンパイラが取り出せるのは pickle ではなくなるため、ソースは復元できません。

| ツール | 元の `.rpyc` | RenMori で処理した後 |
|--------|--------------|----------------------|
| `unrpyc` | `.rpy` に逆コンパイルできる | 失敗 |
| `unrpyc --try-harder` | — | 失敗 |
| `rpycdec` | `.rpy` に逆コンパイルできる | 失敗 |

クローズドプラグインを使うフル保護では、さらにコンパイル済みスクリプトの構造をビルドごとにランダム化するため、ペイロードを完全に復号してもデコンパイラが手がかりにする標準のクラス名が含まれません。詳しくは[スクリプト層](../technical/script-layer.md)を参照してください。

## un.rpyc などの注入式デコンパイラを防ぐには

`un.rpyc` のようなツールは、`game/` に置かれてスクリプトとして読み込まれ、すべてを書き出す仕組みです。RenMori はゲームフォルダ内のスクリプト類のファイル（`.rpyc`、`.rpymc`、`.rpy`、`.rpym`、`.rpe`）を開くことを拒否し、正規のスクリプトは暗号化コンテナからのみ読み込みます。そのため注入されたコードは実行されません。

保護済みビルドでは開発者モードとコンソールも無効になり、`compile`、`dialogue`、`translate` などデータを書き出すサブコマンドも拒否されます。ネイティブランチャーを使うビルド（プラグイン使用時の既定、1.2.5 以降）は、ゲームフォルダにばらのスクリプトや拡張がある場合、起動自体を拒否します。

## AI による自動解析は防げるか

既存ツールを呼び出すだけの AI エージェントは、手作業でツールを実行する人と同じ壁に当たります。ツールが失敗すれば、エージェントにも打つ手がありません。RenMori のビルドは毎回異なるため、あるゲームの解析成果を別のゲームや別のバージョンに流用できず、フォーラムで共有できるような「RenMori アンパッカー」も存在しません。

## Ren'Py ゲームを解析不可能にできるか

できません。これはどんなクライアント側の保護でも同じです。ゲームはプレイヤーのマシン上で動くため、復号ロジックはゲームと一緒に配布され、描画された画面とデコードされた音声は必ずメモリと画面上に現れます。RenMori が防げないものは次のとおりです。

- ゲーム画面のスクリーンショットと録画
- 熟練した攻撃者による、実行中のプロセスからのメモリ抽出
- 特定のゲーム・特定のバージョンに時間をかける専門家による解析
- エンジン自身の Python ファイルの改変など、攻撃者のコードをエンジンに実行させる攻撃

RenMori はオンライン認証やハードウェアへの紐付けも提供しません。RenMori にできるのは、標準的な Ren'Py のアンパックツールとデコンパイルツールをすべて無効化し、ディスク上に平文を残さず、ビルドごとに異なる結果を生成することで、抽出のコストをゲームごと・バージョンごとの専門家による取り組みが必要な水準まで引き上げることです。詳しくは[脅威モデル](../technical/threat-model.md)を参照してください。

## 保護するとゲームは重くなるか

体感できるほどの影響はほとんどありません。約 3.5 GB のアセットを持つ実在の GalGame で計測したところ、ランダム読み込みの追加レイテンシは最大約 0.15 ms で、60 FPS における 1 フレームの 1% 未満でした。コールドキャッシュでのシーケンシャル読み込みは 584 MB/s、`game/` フォルダのサイズ増加は 0.09% にとどまります。コールドスタートは約 1.3 s 長くなりますが、起動時に一度だけです。詳しくは[実ゲームでの実測](../milestones/benchmark-game.md)を参照してください。

## 3 ステップで Ren'Py ゲームを暗号化する

1. Ren'Py ランチャーで *Build Distributions* を実行し、配布用ビルドまたは `.zip` アーカイブを作成します
2. RenMori をインストールしてビルドを保護します。

   ```bash
   pip install renmori
   renmori protect ./dist/MyGame-1.0-pc -o ./dist/MyGame-1.0-pc-protected
   ```

3. 結果を検証し、平文のアセットが残っていないことを確認します。

   ```bash
   renmori verify ./dist/MyGame-1.0-pc-protected
   ```

詳しい手順は[クイックスタート](./quick-start.mdx)にあります。

## その他のよくある質問

### RenMori は有料ですか

無料です。商用作品を含むあらゆる Ren'Py ゲームの保護が無料で、ランタイムもゲームと一緒に無料で再配布できます。

### 対応している Ren'Py のバージョンは

Ren'Py 8.x（Python 3）です。Ren'Py 7.x 以前の Python 2 ベースのエンジンで作られたプロジェクトには対応していません。

### ゲームのソースを変更する必要はありますか

ありません。RenMori は Ren'Py ランチャーが生成した配布用ビルドや `.zip` アーカイブを直接処理します。保護したフォルダはそのまま配布し、ランチャーで再ビルドしないでください。再ビルドすると保護が失われます。

### Steam で配信できますか

できます。[Steam へのリリース](../integration/steam-release.md)を参照してください。ランタイムは Windows・Linux・macOS の実際の Ren'Py エンジンで検証済みで、Steam Deck（Proton）での検証は進行中です。
