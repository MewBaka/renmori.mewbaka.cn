# 脅威モデル

RenMori は、クライアント側の保護にできることとできないことについて誠実な立場をとります。このページは、本プロジェクトおよびその宣伝が主張してよいすべての内容の基準です。何かを約束する前に必ずお読みください。

## 避けることのできない前提

Ren'Py のゲームはプレイヤーのマシン上で動作します。動作するためにはエンジンが自身のアセットを読み込まなければならず、そのため次のことが成り立ちます。

- 復号のロジックはゲームと共に配布される
- 鍵の素材はクライアント上で導出可能である（そうでなければ復号できるものがほかにないため）
- 最終的に描画されたフレームとデコードされた音声は、メモリ上と画面上に存在する

したがって、**いかなるクライアント側のツールも、ゲームを解析不可能にすることはできません**。配布されたバイナリ、デバッガー、そして十分な時間を持つ熟練した執念深い攻撃者は、いずれはどのゲームのどのアセットでも 1 つずつ抽出できます。これがホワイトボックスの問題であり、歴史上のあらゆるローカル DRM 方式は最終的にこの問題によって破られてきました。そうでないと主張する者は、クライアント側の保護にできることを偽っています。

## RenMori が実際に変えること

現実的な手段を、価値の高い順に示します。

1. **既存のツールを無効化する**：`unrpa`、`rpatool`、`RenPack`、`RenpyEx`、`unrpyc`（`--try-harder` と `un.rpyc` による注入を含む）は保護済みビルドに対して失敗する。現実のアセット抽出やスクリプト流出の事例の圧倒的多数は、誰かがこれらのツールのいずれかを実行したにすぎないため、この点は重要であり、これらのツールを呼び出す方法しか知らない AI エージェントも同じ範疇に入る
2. **解析結果を流用できなくする**：ビルドごとの多態化により、1 つのゲームをリバースエンジニアリングして得られるのは、再利用可能なアンパッカーではなく*そのゲームのそのバージョン*専用のツールとなるため、フォーラムで共有できるような「RenMori アンパッカー」は存在しない
3. **古い解析結果を陳腐化させる**：リリースのたびに方式がローテーションされるため、流出した、あるいはリバースエンジニアリングされた古いビルドは新しいビルドに対して役に立たない
4. **ディスク上に平文を残さない**：フォントを含め、いかなる時点でもファイルが復号された状態でファイルシステム上に残ることはない

第 1 項の検証状況：`unrpa`、`unrpyc`（`--try-harder` を含む）、`rpycdec`、およびディスク上に置かれたスクリプトについては、[M1 の成果](../milestones/m1-results.md)と[スクリプト層](./script-layer.md)の記録で確認済みです。`rpatool`、`RenPack`、`RenpyEx` は保護済みビルドに対してまだ実際には実行していません。これらのツールが読み取るのも RPA アーカイブと `.rpyc` ファイルであり、保護済みビルドのディスク上にはこれらのファイルが存在しません。

## RenMori が阻止しない攻撃

以下の点はユーザーに率直に伝えてください。

- 表示内容の**スクリーンショットと画面録画**：定義上、阻止できない
- 熟練した攻撃者による**メモリからの抽出**（例：実行中のプロセスに対する NinjaRipper 級のツール）：チャンク単位の遅延復号はコストを引き上げるが、抽出を防ぐものではない
- 特定の 1 つのゲームを標的とし、時間を費やすことをいとわない**専門家**：そのゲームのそのバージョンに対しては勝てるが、その成果を汎用的なツールに転用することはできない
- **エンジン内で実行されるコード**：ゲームフォルダに置かれたスクリプトや拡張、改変されたエンジンファイルなど、攻撃者自身のコードをエンジンに実行させる手段があれば、Ren'Py 自身のローダーを通じてすべてのアセットを読み出せ、そのようなコードは特定のゲームに限定されない。ネイティブランチャー（プラグイン使用時のデフォルト、1.2.5 以降）を使うビルドは、単体のスクリプトや拡張が存在すると起動を拒否し、ランタイム自身のファイルを鍵に組み込むが、エンジン自身の Python ファイルの改変は検出できず、ランチャーを使わないビルドにはこの検査がない

注入型の抽出ツールを本当に阻止するにはカーネルレベルのアンチチートが必要になりますが、これは対象範囲外であり、プレイヤーにとって敵対的で、パフォーマンス優先と Steam Deck/Proton 対応という目標とも両立しません。

## 本プロジェクトが主張してよい内容

> RenMori は、標準的な Ren'Py のアンパックツールとデコンパイルツールをすべて無効化し、ディスク上に平文を残さず、ビルドごとに異なる結果を生成するため、汎用的なアンパッカーは存在し得ません。抽出のコストを、ゲームごと・バージョンごとに専門家による個別の取り組みが必要な水準まで引き上げます。ゲームを解析不可能にするものではなく、またそうすることもできません。
